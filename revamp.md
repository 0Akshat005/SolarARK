> ## SOLARARK — MASTER RESPONSIVE HERO + WHY SOLARARK REFINEMENT
>
> **Implement the attached desktop and mobile references as one coherent responsive design system.**
>
> The references show the **target composition, information hierarchy, spacing strategy, and mobile behaviour**. Do NOT copy their branding literally.
>
> The final result must remain unmistakably **SolarARK**.
>
> ---
>
> ### 1. ABSOLUTE RULE: PRESERVE THE EXISTING DESIGN SYSTEM
>
> Before modifying anything, inspect the current implementation.
>
> **Preserve exactly:**
>
> * existing SolarARK logo
> * current font family
> * current heading typography
> * current body typography
> * current font weights
> * current type scale
> * current line heights
> * current letter spacing
> * existing SolarARK maroon colour/value
> * existing neutral/background colours
> * existing button colours
> * existing icon language
> * existing spacing tokens
> * existing border/radius conventions
>
> **Do not create a new visual identity.**
>
> **Do not replace the current typography.**
>
> **Do not replace or reinterpret the existing maroon.**
>
> **Do not introduce a new colour palette based on the reference images.**
>
> The references are strictly for **composition, hierarchy, responsive behaviour and art direction**.
>
> ---
>
> # 2. CORE UX STRATEGY
>
> The first screen should guide the visitor through:
>
> **ATTENTION → RELEVANCE → CONFIDENCE → ACTION**
>
> The hero creates attention.
>
> The immediate section below it should remove uncertainty.
>
> The next section should encourage exploration.
>
> Do not make the user process four generic company claims.
>
> Use the **Pareto principle**: surface the small amount of information most likely to influence the user's next decision and push supporting detail deeper into the page.
>
> The user should be able to understand the purpose of this section in **2–4 seconds**.
>
> ---
>
> # 3. DESKTOP HERO
>
> Keep the existing hero content, image, typography and CTA.
>
> Improve composition only where the current implementation differs materially from the reference:
>
> * establish a strong visual focal point
> * maintain readable text contrast over photography
> * keep the text block at a disciplined maximum width
> * preserve deliberate whitespace
> * prevent text from fighting the solar image
> * keep the CTA visually important without making it oversized
>
> The hero should feel premium and editorial rather than like a template.
>
> Avoid additional decorative UI simply to fill space.
>
> ---
>
> # 4. DESKTOP “WHY SOLARARK” SECTION
>
> Replace the current heavy badge strip with the **light editorial information rail shown in the desktop reference**.
>
> This section should visually continue from the hero instead of feeling like a separate component.
>
> ### Structure
>
> Small eyebrow:
>
> **WHY SOLARARK**
>
> Main heading:
>
> **Powering What Matters to You**
>
> Supporting copy:
>
> one concise sentence explaining the customer value.
>
> Below that, create four balanced value points:
>
> **For Your Home**
> Lower bills / practical residential solar value.
>
> **For Your Business**
> Smarter energy / better control of energy costs.
>
> **End-to-End Solar**
> One coordinated solar journey.
>
> **Ongoing Support**
> Continued help beyond installation.
>
> Use the site's **existing approved copy wherever possible** and shorten it rather than inventing new claims.
>
> ---
>
> # 5. DESKTOP VISUAL TREATMENT
>
> The section must NOT look like:
>
> `dark strip → badges → icons → marketing labels`
>
> Instead, make it feel like:
>
> `editorial introduction → four clear value anchors`
>
> Use:
>
> * existing background colours
> * existing typography
> * existing maroon accent
> * small refined line icons
> * generous but controlled whitespace
> * subtle dividers
> * clear alignment
>
> Do not use:
>
> * dark navy background
> * bright yellow/gold icons
> * oversized icon circles
> * floating card stacks
> * glassmorphism
> * heavy shadows
> * gradients
> * excessive border boxes
> * pill/badge UI
>
> The premium feeling should come from **proportion and restraint**.
>
> ---
>
> # 6. DESKTOP GRID PROPORTION
>
> Do not force four equal columns mechanically.
>
> Use a sensible max-width content container and ensure:
>
> * equal visual rhythm
> * consistent icon positioning
> * heading baselines align
> * supporting-copy lengths feel balanced
> * dividers sit in the whitespace between items
> * no column looks empty or overloaded
>
> The fourth item may visually connect toward the following section/image treatment if that improves the composition, but do not add decorative imagery without purpose.
>
> ---
>
> # 7. MOBILE MUST BE A TRUE RECOMPOSITION
>
> **Do NOT shrink the desktop section.**
>
> Use the mobile reference as the target information architecture.
>
> On mobile:
>
> `WHY SOLARARK`
>
> **Powering What Matters to You**
>
> one short supporting sentence
>
> followed by a compact **2 × 2 value grid**.
>
> ---
>
> ### Mobile value hierarchy
>
> **Home**
> Lower bills.
>
> **Business**
> Smarter energy.
>
> **End-to-End**
> One team.
>
> **Support**
> We're with you.
>
> These are examples of the desired **content density**, not permission to discard approved SolarARK messaging.
>
> Use the best existing approved copy and remove only redundant wording.
>
> ---
>
> # 8. MOBILE DESIGN PRINCIPLES
>
> The mobile version should feel **designed for a phone**, not adapted from desktop.
>
> Use:
>
> * approximately 18–20px side margins, adapting to existing spacing tokens
> * compact vertical rhythm
> * strong alignment
> * small line icons
> * short headings
> * one or two lines of supporting copy
> * subtle dividers
> * no unnecessary cards
>
> Every element must justify its space.
>
> ---
>
> # 9. IMPORTANT MOBILE COMPOSITION IMPROVEMENT
>
> After the four value items, do NOT repeat another four-item information block.
>
> Instead, create **one concise transition element** that bridges confidence into the services section.
>
> Example concept:
>
> **A Cleaner, Brighter Maharashtra**
>
> Sustainable energy for stronger communities.
>
> Keep it visually understated and integrated into the page.
>
> This is the single emotional reinforcement point.
>
> Do not turn it into another giant card.
>
> ---
>
> # 10. MOBILE CTA STRATEGY
>
> The hero already contains the primary:
>
> **Get a Quote**
>
> Do not insert another oversized CTA immediately below it.
>
> The value section is for **confidence**, not conversion repetition.
>
> Only show arrows on items that are genuinely interactive.
>
> ---
>
> # 11. MOBILE BREAKPOINTS
>
> Design intentionally for:
>
> **320px**
> **360px**
> **375px**
> **390px**
> **430px**
>
> At 375–430px:
>
> use the preferred **2 × 2 grid**.
>
> At very narrow widths:
>
> transition gracefully to compact rows only when necessary.
>
> Never allow:
>
> * horizontal scrolling
> * awkward word wrapping
> * oversized blank space
> * clipped content
> * excessive section height
> * tiny interaction targets
>
> ---
>
> # 12. RESPONSIVE TYPOGRAPHY
>
> Preserve the **existing typography family and visual character**.
>
> Responsively scale only according to the current site's type system.
>
> Do not arbitrarily make mobile headings huge.
>
> The reference's large heading is a **composition reference**, not an instruction to exaggerate font sizes.
>
> Prioritise:
>
> **readability → hierarchy → rhythm**
>
> ---
>
> # 13. ICONOGRAPHY
>
> Reuse the existing SolarARK icon set/style whenever possible.
>
> Keep icons:
>
> * small
> * refined
> * consistent stroke weight
> * secondary to typography
>
> Do not put them inside giant decorative circles.
>
> Do not use emoji-like icons.
>
> Do not mix different icon families.
>
> ---
>
> # 14. COLOUR USAGE
>
> **Keep the existing colour scheme EXACTLY.**
>
> The current maroon remains the brand accent.
>
> Do not:
>
> * make the whole section maroon
> * introduce navy
> * introduce green
> * introduce gold
> * recolour existing components
> * invent new colour tokens
>
> Use the current colour tokens more intelligently through **restraint and hierarchy**.
>
> ---
>
> # 15. CONTENT RULES
>
> Apply the Pareto principle aggressively.
>
> Remove:
>
> * repetitive descriptions
> * generic corporate filler
> * duplicate sustainability messaging
> * unnecessary adjectives
> * marketing clichés
>
> Retain:
>
> * user relevance
> * practical benefit
> * process confidence
> * support reassurance
>
> **Never invent numerical claims, certifications, warranties, customer counts, project counts, government affiliations, authorization status, or performance figures.**
>
> Only use verified/approved SolarARK content.
>
> Current solar UX case studies similarly emphasize clarity, service comprehension, credible proof, and a guided conversion journey rather than simply increasing the amount of content. ([Behance][1])
>
> ---
>
> # 16. DESKTOP + MOBILE SHOULD FEEL LIKE ONE SYSTEM
>
> Do NOT make desktop and mobile look like separate redesigns.
>
> They should share:
>
> **same brand → same type → same colour → same icon language → same content hierarchy**
>
> while changing:
>
> **layout → density → spacing → information presentation**
>
> Desktop = editorial horizontal composition.
>
> Mobile = compact vertical decision journey.
>
> ---
>
> # 17. DO NOT OVER-DECORATE
>
> Avoid adding visual elements simply because the section has whitespace.
>
> Do not fill empty space with:
>
> * random illustrations
> * decorative shapes
> * additional badges
> * statistics
> * unnecessary photographs
> * oversized icons
>
> Intentional whitespace is part of the design.
>
> ---
>
> # 18. IMPLEMENTATION SAFETY
>
> Before implementation:
>
> 1. Inspect the existing component hierarchy.
> 2. Find the shared design tokens.
> 3. Identify the current hero and post-hero components.
> 4. Modify only the necessary components/styles.
> 5. Reuse existing variables instead of hardcoding new visual values.
> 6. Do not modify unrelated sections.
> 7. Preserve links and functionality.
> 8. Preserve accessibility.
> 9. Preserve existing responsive conventions where they are already correct.
>
> ---
>
> # 19. QA REQUIREMENT
>
> After implementation, inspect:
>
> **Desktop:** 1280 / 1440 / 1600 / 1920
>
> **Mobile:** 320 / 360 / 375 / 390 / 430
>
> Check the actual rendered result, not just the CSS.
>
> Specifically verify:
>
> * hero remains dominant
> * post-hero section is immediately understandable
> * no oversized desktop spacing
> * mobile does not feel like stacked desktop cards
> * headings wrap intentionally
> * all four value points remain scannable
> * section height is economical
> * no horizontal overflow
> * CTA hierarchy remains clear
> * typography remains SolarARK
> * colours remain SolarARK
>
> ---
>
> # 20. FINAL ART-DIRECTION TEST
>
> The result should feel like:
>
> **a premium solar/EPC brand designed by an experienced product designer**
>
> with:
>
> **clarity + warmth + credibility + precision**
>
> and not:
>
> **AI-generated UI + badges + generic cards + excessive gradients**
>
> The user journey should visually read:
>
> **Hero promise**
>
> ↓
>
> **“Why SolarARK?” — immediate reassurance**
>
> ↓
>
> **Four essential reasons**
>
> ↓
>
> **One emotional/value bridge**
>
> ↓
>
> **Services / deeper exploration**
>
> **Do not consider the work complete until desktop and mobile both achieve this hierarchy while visibly retaining the CURRENT SolarARK typography and colour system.**
